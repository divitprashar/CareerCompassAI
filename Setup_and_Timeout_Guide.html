⚙️ Part 1 — Complete Installation Guide

Follow every step below in order. Steps 1–4 require an internet connection. After setup the app works fully offline.

📋 Before you begin — checklist Windows 10 or 11  |  4 GB RAM minimum (8 GB recommended)  |  5 GB free disk space  |  Internet connection  |  20–30 minutes
🐍
Step 1 — Install Python 3.11
Python is the programming language that runs the app
Required
A
Download Python

Open your browser and go to: https://www.python.org/downloads/

Click the large yellow button: "Download Python 3.11.x"

This saves a file named something like python-3.11.9-amd64.exe to your Downloads folder.

B
Run the installer

Double-click the downloaded .exe file to open the installer.

🚨 CRITICAL — Do this before clicking anything else: At the very bottom of the first installer screen, check the box that says:

☑ Add Python 3.11 to PATH

If you skip this, Python will not work from the command line and setup.bat will fail.

After checking the PATH box, click "Install Now".

If Windows asks "Do you want to allow this app to make changes?" — click Yes.

Wait for the progress bar to complete (1–3 minutes), then click Close.

C
Verify Python is installed correctly

Press Windows + R → type cmd → press Enter.

In the black Command Prompt window, type:

python --version

You should see something like: Python 3.11.9

Also verify pip (Python's package manager):

pip --version

You should see something like: pip 24.x.x from C:\Users\...

⚠
If python --version shows an error or opens the Windows Store

This means Python was not added to PATH. Fix it:

  • Press Windows → search Environment Variables → click "Edit the system environment variables"
  • Click Environment Variables button
  • Under User variables, find Path → click Edit
  • Click New and add: C:\Users\YOUR_NAME\AppData\Local\Programs\Python\Python311
  • Click New again and add: C:\Users\YOUR_NAME\AppData\Local\Programs\Python\Python311\Scripts
  • Click OK on all windows, then close and reopen Command Prompt

Step 2 — Install Ollama
Ollama is the engine that runs the AI model locally on your laptop
Required
A
Download Ollama

Open your browser and go to: https://ollama.com/download

Click "Download for Windows".

This saves a file named OllamaSetup.exe (~100 MB) to your Downloads folder.

B
Run the Ollama installer

Double-click OllamaSetup.exe.

If Windows SmartScreen shows a warning: click "More info" → "Run anyway". This is safe — Ollama is a well-known open-source tool.

The installer runs silently — you will see a small progress dialog, then it will disappear. That means it is done.

Ollama installs to: C:\Users\YOUR_NAME\AppData\Local\Programs\Ollama\

It also registers itself as a Windows background service that starts automatically.

C
Verify Ollama is installed

Open a new Command Prompt window (important — existing windows won't have the new PATH).

ollama --version

You should see: ollama version 0.x.x

Also check the Ollama service is running:

ollama list

This should show an empty table (no models yet) — that is correct at this stage.

D
Download the AI model (llama3.2:3b)

In Command Prompt, run:

ollama pull llama3.2:3b

This downloads the Llama 3.2 3B model (~2 GB). You will see a progress bar:

pulling manifest...
pulling 966de95ca8a6... ████████████████ 100% 2.0 GB
verifying sha256 digest
writing manifest
success

This takes 5–20 minutes depending on internet speed. Do not close the window.

After it finishes, verify the model is ready:

ollama list

NAME                ID              SIZE
llama3.2:3b       a80c4f17acd5    2.0 GB
⚠
If ollama command is not found after install

Add Ollama manually to PATH:

  • Press Windows + R → type cmd → Enter
  • Run this command to add Ollama to user PATH permanently:
setx PATH "%PATH%;%LOCALAPPDATA%\Programs\Ollama"
  • Close and reopen Command Prompt, then try ollama --version again

⏱️ Part 3 — Why Timeouts Happen

A timeout means the app waited for a response from the AI model but it took too long. There are three different causes:

Timeout TypeWhat causes itWhen it happens
Connection Timeout Ollama is not running or not started yet Immediately — app can't even reach Ollama
Read Timeout Ollama is running but the model is taking too long to generate a reply on a slow CPU After 30–120 seconds — the most common issue
Browser Timeout Browser gives up waiting before the server responds After ~60–120 seconds in some browsers
⚠️ Root cause on slow laptops The Llama 3.2 3B model has 3.21 billion parameters. On a CPU (no GPU), each token takes ~0.3–1 second to generate. A 200-word reply = ~250 tokens = 75–250 seconds on an older laptop. The original code used a 120-second timeout which was not enough.

🔧 Part 4 — What Was Fixed in app.py

Four specific changes were made to eliminate timeout errors and speed up responses:

Fix 1 — Increased and split the timeout

❌ Before (caused timeouts)

  • timeout=120 — single 120-second limit
  • Applied to both connection AND response generation
  • Slow CPUs regularly exceeded 120 seconds

✅ After (fixed)

  • timeout=(10, 300) — connection: 10s, read: 300s
  • 5-minute read timeout — handles any slow CPU
  • Separate connection timeout catches Ollama-not-running fast
# Before — one timeout for everything:
resp = requests.post(OLLAMA_URL, json=payload, timeout=120)

# After — separate connect and read timeouts:
resp = requests.post(OLLAMA_URL, json=payload, timeout=(10, 300))
# ↑ ↑
# connect(s) read(s)

Fix 2 — Reduced num_predict (token limit)

num_predict 512 → 200
Maximum tokens the model generates per reply. 512 tokens = up to ~380 words. 200 tokens = up to ~150 words — still a complete answer but 2.5× faster to generate.

Fix 3 — Reduced context window (num_ctx)

num_ctx default 4096 → 2048
The amount of text the model loads into memory at once. Smaller context = less RAM used = faster processing. 2048 tokens is enough for a full career counseling session.

Fix 4 — Added top_k and top_p sampling limits

top_k / top_p 20 / 0.8
These limit how many word choices the model considers at each step. Lower top_k = smaller vocabulary search = faster token generation. Default is top_k=40; setting to 20 reduces computation per token.

Fix 5 — Shortened the system prompt

❌ Before — long system prompt

  • ~200 words of instructions
  • Full field list embedded every request
  • More tokens = more processing time before first reply

✅ After — tight system prompt

  • ~50 words of core instructions
  • Explicit instruction: keep replies under 120 words
  • Fewer prompt tokens = faster time-to-first-token

Fix 6 — Capped conversation history at 10 messages

recent_messages = session["messages"][-10:] Last 10 only
Without this, every new message sends the entire conversation history to the model. After 20 messages the payload becomes very large, making each request progressively slower. Keeping only the last 10 messages keeps payload size constant.
